# Multi-Tenant Database Work Plan

Requested scope: multi-tenant database support is required.

1. Database catalog and manager
   - Added a server-side tenant database catalog under `DATA_DIR/databases/catalog.txt`.
   - Added `TenantDatabaseManager` that keeps `default` mapped to the existing
     root database and opens tenant databases under `DATA_DIR/databases/{name}`.

2. Request-level database selection
   - HTTP requests can select a database through `X-Neo4r-Database`, `?db=name`,
     or a JSON `"database":"name"` field.
   - Query, graph, statistics, storage, metadata-log, profile, backup, and restore
     paths now use the selected database where applicable.

3. Database admin API and UI
   - Added `GET /api/admin/databases` and `POST /api/admin/databases`.
   - Added web console controls for database selection and database creation.

4. DB-scoped auth
   - Extended web user tokens with `database_roles` such as
     `tenant_a=writer,tenant_b=reader`.
   - Existing tokens without `database_roles` remain global for compatibility.
   - Added web UI support for issuing a token scoped to the selected database.

5. Correctness tests
   - Added tenant isolation coverage proving data inserted in `tenant_a` is not
     visible in `default`.
   - Added DB-scoped token coverage proving a tenant token can write to its
     allowed DB but cannot access `default`.

Verification target:

- `cargo fmt --all`
- `cargo test -p neo4r-server web_console_isolates_tenant_databases_and_scopes_tokens -- --nocapture`
- `cargo test -p neo4r-server web_console_serves_index_and_graph_api --quiet`
- `cargo test --workspace --quiet`
- `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=sdks/python python3 -m unittest discover -s sdks/python/tests -v`
- `git diff --check`

     native result pages.

   - Added `crates/neo4r-client/examples/basic_usage.rs` for a runnable Rust
     SDK example.

3. Python SDK
   - Added `sdks/python/neo4r_client`.
   - Implemented blocking native frame IO, query payload encoding, result row
